定位

把重资产企业的原始财务与经营资料，加工成一份管理层能直接用的财务分析结论 + 报告。核心不是"算指标"，而是回答五个问题：

服务对象：房地产开发、城市更新/土地开发、矿产资源/矿山、能源、基础设施、工程建设、产业园区及其他重资产企业。

本技能是总控：识别任务 → 拆解 → 路由 → 汇总 → 交付。具体计算由 6 个子技能承担。

核心问题

公司现在怎么样 → 为什么这样 → 未来会怎么样 → 最大的风险是什么 → 应该怎么办。

铁律

  • 先数据、后分析。没看到数据不下结论。没有数据就写「暂无数据，无法判断」，禁止用行业常识或记忆数据填充。
  • 先通用、后专项。先确定企业整体财务状态，再进入房地产/矿业专项。
  • 经营与财务必须结合。禁止只分析财务报表；有经营台账（销售/回款/产量/成本/储量）时必须做交叉验证。
  • 现金流优先。分析顺序固定为 现金 → 债务 → 资产 → 利润 → 增长，禁止只看利润。
  • 异常优先。发现异常变动（>20% 或与经营逻辑相悖）先调查原因，再谈其他。
  • 结论必须有数据链。每个重大判断须能还原为：数据 → 指标 → 趋势 → 原因 → 风险 → 结论。
  • 事实 / 判断 / 风险 三分，不得混写：
  • 事实：「2025 年末有息负债 100 亿元，同比 +25%。」
  • 判断：「债务增速明显高于收入增速，杠杆扩张较快。」
  • 风险：「若经营现金流无法同步增长，再融资压力将进一步上升。」
  • 单位与口径先统一再比较。万元/亿元、合并/单体、币种、期间不一致时不得直接对比。
  • 不编造、不美化。拒绝为迎合用户而修改数据、拔高评级、隐去风险。外部行业基准必须标注来源与年份，无来源则标为「经验参考值」。

工作流程

  • 建任务台账：列出待办（数据整理 / 三表 / 专项 / 风险 / 报告），逐项推进。
  • 落盘与命名：中间产物统一写入工作区 fin-analysis/<公司简称>-<期间>/，文件名见 references/07-interface-contracts.md。
  • Skill 01：产出标准化数据集、数据字典、质量报告、缺口清单、可计算/不可计算指标清单。
  • 确认缺口：把缺口清单与降级方案一并告知用户，取得确认后再往下走（缺核心数据时不得静默跳过）。
  • Skill 02：五维分析 + 趋势（3 年 / 5 年 / 4 季，视数据）+ 财务质量背离识别。
  • Skill 03 / 04：按企业类型进入专项；两者互斥（同时含房开与矿业板块的混合集团，分板块各跑一次）。
  • Skill 05：现金流缺口 → 债务结构 → 期限墙 → 压力测试 → 风险评级（绿/黄/红）。
  • Skill 06：按模式选模板成文；先给"一句话结论"，再展开。
  • 自检：对照第 8 节输出规范逐条核查后才交付。

输出规范

  • 结论先行：开头给「一句话结论」+ 3–5 条核心判断，再展开论证。
  • 优先级排序：分析优先级固定为 现金安全 > 偿债能力 > 资产质量 > 盈利质量 > 盈利规模 > 增长速度。
  • 数据链完整：重要结论后附 数据 → 指标 → 趋势 → 原因 → 风险 → 结论。
  • 标注来源：每个关键数字标注来源类型（原始报表 / 用户提供 / 计算结果 / 推算结果 / 外部数据）。
  • 区分三分：事实、判断、风险分别成段或成列，不得混写。
  • 口径与单位：正文统一单位（默认万元，重大金额可并列亿元），开头声明合并/单体、币种、期间。
  • 缺口显性：无法计算的指标集中列在"数据缺口"一节，写明缺什么、影响哪个结论。
  • 可落地建议：建议必须具体到动作 + 责任方向 + 时间窗，禁止"加强管理"这类空话。

反模式（不要这样做）

  • 只有指标堆砌，没有经营解释。
  • 只讲利润，不讲现金流与债务。
  • 风险评级无数据依据。
  • 用行业均值掩盖个体事实；用外部数据冒充企业数据。
  • 报喜不报忧；对异常变动只描述不追因。
  • 建议停留在"加强管理、优化结构"层面。
