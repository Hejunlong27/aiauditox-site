审计工作底稿逆向工程与自动化开发

新底稿模板进，配置驱动的填表程序、数据血缘与本地 EXE 出

audit-workpaper-reverse-engineering基础支撑单体工具型版本 v1.0.1

技能说明

读取新的审计底稿 Excel 模板与总账/明细账/科目余额表/辅助核算等原始数据表头，完成底稿结构与源数据结构分析、字段映射候选与人工确认，生成配置驱动的填表流水线，产出填充底稿副本、SQLite 双向数据血缘、Decimal 独立复算的勾稽报告与异常报告，并可打包成项目专属的 Windows 本地 EXE。首次调用强制确认数据脱敏与处理边界，未确认不读数据；原始文件只读、映射须确认、差异不调平、血缘双向可溯。

定位

把一个新的底稿模板 + 新的原始数据表头/样例适配成一套可重复运行的项目程序。每次项目都必须重新分析、重新确认映射，再生成独立的项目配置和 EXE。技能不预置任何客户字段、科目编码或单元格坐标，避免把上一家客户的结构带进下一家。

核心问题

把「一套新底稿模板 + 一批新原始数据」变成可重复运行、可追溯、可交付的项目程序，而不是为某一张固定底稿写死代码。

铁律

  • 隐私闸门优先 —— 未确认不读数据。
  • 原文件只读 —— 禁止覆盖模板或原始数据；写回必须另存副本，并给出原始文件哈希未变的证据。
  • 配置驱动 —— 项目字段、筛选、坐标和公式不能硬编码进通用程序，只能写进项目配置。
  • 映射须确认 —— 歧义字段、金额单位、期间、借贷方向和审计判断必须由用户确认，未确认映射默认被拒绝。
  • 公式不臆测 —— openpyxl 不计算公式，不得把空缓存值当成零；勾稽一律用 Python Decimal 独立复算。
  • 差异不调平 —— 勾稽失败只生成报告，不得修改数据凑平，任何差异都保留原值与来源。
  • 血缘必须双向 —— 目标单元格可追溯全部来源记录，源记录可反查全部引用目标，缺一侧即视为血缘不完整。
  • 格式保留可验证 —— 工作表顺序、合并、冻结、打印区域、隐藏状态、行列尺寸等必须比对；无法保留的高级对象要明确列出。
  • 不编造专业结论 —— 业务用途、审计逻辑和异常解释证据不足时列为待确认事项，不得补全为确定结论。
  • 不对外发布 —— 上传网盘、SkillHub、公开仓库或其他外部动作必须先取得用户明确授权。

工作流程

  • 阶段 0 · 确认与隔离：完成强制脱敏确认，为项目建立独立目录并生成 privacy_gate.json，原始模板与原始数据全程只读。
  • 阶段 1 · 结构分析：运行 inspect_workbook.py 与 inspect_source_data.py，脚本给事实，AI 负责解释；业务用途只给候选与证据。
  • 阶段 2 · 审计逻辑与映射：运行 analyze_mapping.py 与 build_mapping.py 产出映射候选，解释依据，歧义项暂停并请用户确认。
  • 阶段 3 · 项目配置：按配置规范建立 sources / mappings / writes / calculations / reconciliations，项目专属字段只进配置，不进通用引擎。
  • 阶段 4 · 执行与复核：运行 run_pipeline.py，产出填充底稿、lineage.sqlite3、勾稽报告、异常报告与执行报告；差异只报告不调平。
  • 阶段 5 · 桌面程序与 EXE：运行 build_desktop_app.py 与 package_exe.py，必须通过内置 --self-test，EXE 不联网、不上传数据。
  • 阶段 6 · 交付：交付技能与项目目录、配置文件与全部产物、测试结果、已知限制，以及原始文件未被修改的哈希证据。

输出规范

  • Skill 能被目标 Agent/Harness 识别，且首次调用先执行脱敏确认。
  • 模板和源数据可由脚本解析并输出结构化分析。
  • 映射候选可解释，歧义项经用户确认后固化。
  • 配置驱动流水线可生成填充底稿副本。
  • 至少一项正向血缘查询和一项反向血缘查询通过。
  • 勾稽 pass/fail/unknown 均能报告，差异不自动调平。
  • Windows EXE 可打包、可启动、内置自测退出码为 0。
  • 测试套件全绿，已知限制和未完成项写清楚。
